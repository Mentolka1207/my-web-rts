# Recon-карта: Minimal Web RTS (Neo-Drone Swarm & Patrolling AI)

Дата разбора: 2026-10-29. Объект: `github.com/Mentolka1207/my-web-rts`, ветка `main`, коммит `a1919fb`.
Цель: понять, как игра устроена сейчас, и что нужно достроить, чтобы она стала **продаваемым продуктом / основой своего проекта**.

Это собственный репозиторий автора под лицензией MIT, поэтому разбор сделан **по исходному коду**, а не по внешним
признакам. Каждое утверждение ниже имеет ссылку `файл:строка`. Где я не смог проверить — так и написано.

## 2. Как это работает (архитектура в одном экране)

```
index.html ─ подключает 24 <script> по порядку (глобальные переменные, без модулей и сборщика)  index.html:199-222
   │
   ├─ config.js     константы: сетка 22×22, клетка 2, типы юнитов, лимиты волн           config.js:88-135
   ├─ prng.js       Mulberry32, глобальный сид 4242 (setSeed нигде не вызывается)         prng.js:47
   ├─ grid.js       карта: внешние стены + 25 попыток поставить стену по PRNG              grid.js:16-22
   ├─ flowfield.js  BFS → integration field → flow field; 2 генератора (игрок / враги)     flowfield.js:214-215
   ├─ spatialhash.js  сетка ячеек 4.0 для поиска ближайшей цели и расталкивания
   ├─ units.js / models.js / instancing.js / healthbar.js  юниты, процедурные модели, InstancedMesh
   ├─ resources.js  3 кристалла, захват прогрессом [-1..1]                                resources.js:118-213
   ├─ economy.js    energy=100, +5/с, производство                                          economy.js:5-52
   ├─ ai.js         волны каждые 60 с, босс на 10/20/…, диверсии при 3/3 точках            ai.js:5, 33-102, 113
   ├─ audio.js      процедурный звук Web Audio (813 строк)
   ├─ ui.js / input.js / minimap.js / benchmark.js  HUD, управление, профайлер
   └─ main.js       animate(): rAF → фиксированный шаг 1/30 с, ≤4 тиков за кадр           main.js:49, 476-486
                    stepSimulation(): ресурсы → доход → волны → spatial hash → FSM союзников
                    → ИИ врагов → смерти → победа/поражение → 2 прохода расталкивания       main.js:55-450
```

**Где на самом деле идёт симуляция.** Вся логика боя выполняется в главном потоке над обычными JS-объектами
(`unit.mesh.position`, `unit.hp`) в `stepSimulation` (`main.js:101-273`). SoA-мир `simWorld` только выделяет и освобождает слоты
(`units.js:63,112`, `main.js:289,307`). Методы `simWorkerManager.step`, `syncToObjects`, `syncFromObject` нигде не вызываются,
а воркер `js/sim_worker.js` (49 строк) возвращает буфер без вычислений (`sim_worker.js:23-43`). Подробнее — §8.

## 4. Пользовательские сценарии

```
F01 Сыграть партию до победы (core loop)
    S01 «Играть» -> S02 (захват точек, производство, оборона, атака штаба) -> S05 «ПОБЕДА»
    кликов до начала игры: 1. Длина партии не ограничена — волны бесконечны (ai.js:33-102)
    edge: всё 3/3 под контролем → раз в 35 с диверсия 2 Разведчика + Танк (ai.js:110-150);
          лимит 50 врагов на карте режет волну (config.js:135, ai.js:93-94);
          босс со щитом 400: пока щит есть, HP не падает (main.js:234-248)

F02 Отдать приказ группе
    десктоп: зажать ЛКМ и тянуть -> ПКМ по земле/врагу  = 2 действия
    мобайл:  «🖐 Карта» -> «⬚ Рамка» -> тянуть -> тап    = 3 действия (или долгое нажатие)
    edge: точка в стене/вне карты → sanitizeTargetPosition (input.js:177); цель недостижима → flow-вектор 0, юнит идёт напрямую (main.js:156)

F03 Произвести юнита
    S02 кнопка «Дрон/Разведчик/Танк» = 1 клик
    edge: нет энергии → кнопка disabled (economy.js:29-40); спавн у базы в ближайшей свободной клетке (units.js:31)

F04 Применить способность
    выделить -> Q / E / R(F) или кнопка в панели = 2 действия (units.js:233-318)

F05 Захватить кристалл
    выделить -> ПКМ в кольцо радиуса 2.8 -> ждать (≈4.5 с одним юнитом: 1/0.22) (resources.js:6, 160-170)
    edge: в кольце есть и свои, и чужие → прогресс стоит (resources.js:160-161)

F06 Проиграть и начать заново
    S05 «Играть снова» -> location.reload() -> S01 «Играть» = 2 клика (index.html:194)

F07 (разработчик) Бенчмарк
    F3 -> «500» -> «Сбросить»
    edge: убитые в бенчмарке враги попадают в итоговую статистику партии (видел: 15 убитых при 0 волн, S05)
```

## 7. Что уже сильно (по коду, не по README)

## 9. Чего нет и что нужно построить для продукта

Сгруппировано; полный список с приоритетами — в `features.csv`.

1. **Каркас продукта:** пауза, настройки, сохранение настроек, экран загрузки, обучение вместо стены текста, лицензии сторонних библиотек.
2. **Контент и реиграбельность:** сейчас 1 карта (фиксированный сид), 1 режим, бесконечные волны без конца партии кроме сноса штаба. Нужны: карты как данные, выбор сложности, хотя бы режим skirmish и/или короткая кампания, рекорды.
3. **Мобильный UX и производительность:** свёрнутые по умолчанию инструкции, крупные тач-цели, объединение статичной геометрии (стены, рельсы) в instanced/merged меши, настройка качества теней.
4. **Локализация:** все строки зашиты по-русски в `index.html` и JS (`ai.js`, `ui.js`, `resources.js`). Для продажи нужен как минимум английский.
5. **Честная техническая часть:** либо реально вынести симуляцию в воркер, либо убрать заявление из README; привязать headless-тест к настоящему коду через `tests/helpers/loadGame.js`.
6. **Дистрибуция:** PWA/офлайн (опыт есть — ЛР2), сборка в один файл/минификация, страница игры, аналитика без персональных данных.
7. **(Опционально) Мультиплеер:** детерминизм сейчас неполный — частицы и косметика на `Math.random` (это не страшно), но очередь flow field обрабатывается раз в кадр вне фиксированного тика (`main.js:468-473`), а приказы применяются сразу. Lockstep-сеть потребует это переделать и сервер-ретранслятор.

## 10. Что нельзя / не нужно «копировать»

Чужого в проекте почти нет: код, модели, текстуры и звуки — твои и процедурные. Два пункта, которые касаются продажи:

- **three.js** распространяется по MIT; по тексту MIT уведомление об авторских правах должно быть включено во все копии.
  В `libs/three.min.js` заголовка с лицензией нет (файл начинается с `var THREE=(()=>`). Нужен файл с лицензиями сторонних библиотек.
  Лицензия three.js: https://github.com/mrdoob/three.js/blob/dev/LICENSE
- **Твой собственный репозиторий под MIT.** Текст `LICENSE` прямо разрешает любому «use, copy, modify, merge, publish,
  distribute, sublicense, and/or sell copies». То есть кто угодно может законно продавать форк этой версии.
  Если планируешь продавать — реши вопрос лицензии для будущих платных версий до релиза (я не юрист; это вопрос к юристу).
- Упоминание Supreme Commander в README (README:22) — только как пример жанра; ассетов оттуда нет.

## 11. Размер работы

| что | оценка | почему |
|---|---|---|
| Полировка до продаваемой одиночной веб-игры (п.1, 3, 4, 5, 6) | **M** — несколько недель | движок готов, нужен продуктовый каркас, мобильный UX, i18n, оптимизация статики |
| + контент (3–5 карт, сложности, skirmish, короткая кампания) | **L** — около квартала | основная работа — гейм-дизайн и баланс, а не код |
| + сетевой мультиплеер | **XL** — переоценить объём | нужен настоящий детерминизм, сервер, матчмейкинг |

# 🛰️ План задач и развития проекта `my-web-rts`

Документ содержит список технических, геймплейных и медийных задач для развития браузерной 3D RTS на базе Three.js с процедурной генерацией ассетов.

---

## 1. Профилирование, телеметрия и бенчмарки (Data & Telemetry)

Цель этапа — собрать точные метрики производительности движка для поиска узких мест и наглядной демонстрации преимуществ выбранной архитектуры.

- [x] **Встроенный HUD-профайлер (Debug Overlay):**
  - [x] Вывести время кадра ($\text{ms}$) и частоту кадров ($\text{FPS}$) в реальном времени.
  - [x] Добавить отдельные таймеры (`performance.now()`) для замера времени расчёта каждого подмодуля за тик:
    - Построение поля интеграции Дейкстры и векторного поля (Flow Fields).
    - Обновление Spatial Hash Grid и разрешение локальных коллизий.
    - Тик конечных автоматов (FSM) и логики способностей (`Siege Mode`, щиты, ускорение).
    - Синтез активных звуков в Web Audio API.
  - [x] Вывести счётчик `renderer.info.render.calls` (Draw Calls) и `triangles`.
- [x] **Автоматизированный стресс-тест (Benchmark Scene):**
  - [x] Создать тестовый пресет сцены с автоматическим спавном $100$, $500$, $1000$ и $1500+$ юнитов, идущих через узкие проходы навстречу друг другу.
  - [x] Добавить переключатель алгоритма коллизий в дебаг-меню: наивный перебор $O(N^2)$ против Spatial Hashing $O(N)$ для наглядного сравнения просадки $\text{FPS}$.
  - [x] Зафиксировать итоговый вес бандла (в $\text{KB}$) и потребление видеопамяти процедурными PBR-текстурами.

## 2. Архитектурная оптимизация и масштабирование (Core Engine)

Цель этапа — разгрузить главный поток браузера и подготовить движок к масштабным сражениям и сетевой синхронизации.

- [x] **Вынос симуляции в `Web Worker`:**
  - [x] Отделить математическую модель мира (координаты, скорости, состояния FSM, сетку Flow Fields) от объектов `THREE.Mesh`.
  - [x] Перевести хранение данных юнитов на плоские типизированные массивы (`Float32Array`, `Int32Array`) по принципу Data-Oriented Design (SoA — Structure of Arrays).
  - [ ] Полноценный запуск боевого цикла в воркере: *SoA-прототип готов, рабочий цикл в главном потоке на 30 Гц обеспечивает детерминизм и запуск по file:/// без ограничений CORS*.
- [x] **Оптимизация рендеринга (GPU Instancing):**
  - [x] Перевести отрисовку однотипных юнитов и снарядов на `THREE.InstancedMesh` для сокращения Draw Calls до минимума.
  - [x] Инстансирование статической геометрии (`InstancedMesh` для стен и защитных оголовков в `js/terrain.js` — снижение Draw Calls стен до 2).
  - [x] Переписать 3D-биллборды полосок здоровья (Health Bars) на единый инстансированный меш с передачей текущего процента $\text{HP}$ и состояния щита через кастомный атрибут шейдера (`InstancedBufferAttribute`).
- [x] **Кэширование и оптимизация Flow Fields:**
  - [x] Внедрить ленивый пересчёт (Lazy Evaluation) и очередь запросов на построение векторных полей, чтобы при одновременных кликах не пересчитывать несколько гридов в один и тот же кадр.
  - [x] Добавить иерархический сброс кэша полей только для тех секторов карты, где изменилась проходимость (например, при развёртывании юнитов в `Siege Mode`).
- [x] **Детерминированный цикл (Fixed Timestep & Lockstep-ready):**
  - [x] Отвязать логику симуляции от `requestAnimationFrame` и перевести её на фиксированный шаг времени (например, $\Delta t = 50\text{ ms}$ или $20\text{ ticks/sec}$) с интерполяцией рендера.
  - [x] Заменить вызовы `Math.random()` в игровой логике на детерминированный генератор псевдослучайных чисел (PRNG с сидом) для возможности воспроизведения реплеев и запуска Headless-симуляции.

## 3. Геймплей, тактический ИИ и процедурный контент (Gameplay & Polish)

Цель этапа — углубить тактическое взаимодействие юнитов и расширить возможности процедурной генерации без привлечения внешних ассетов.

- [x] **Развитие конечного автомата (FSM) и управления строем:**
  - [x] Добавить выбор типа боевой формации при отправке группы: шеренга (Line), клин (Wedge), защитное кольцо (Circle) вокруг дальнобойных юнитов в `Siege Mode`.
  - [x] Улучшить поведение в состоянии `Attack` / `Chase`: добавить учёт фокуса огня (Target Priority) — приоритет по целям с малым $\text{HP}$ или опасным дальнобойным единицам.
  - [x] Доработать логику `Siege Mode`: автоматическое занятие выгодной дистанции и запрет на случайное смещение от толкания союзниками.
- [x] **Улучшение процедурной графики (Canvas PBR):**
  - [x] Расширить генератор текстур на `HTMLCanvasElement`: помимо базового цвета (`map`), шероховатости (`roughnessMap`) и металличности (`metalnessMap`), генерировать процедурные карты нормалей (`normalMap`) и свечения (`emissiveMap`) для индикации активных способностей (овердрайв, заряд щита).
  - [x] Добавить процедурные эффекты частиц (взрывы, следы от снарядов, искры при попадании по щиту) на базе `THREE.Points` или инстансированных примитивов.
- [x] **Модернизация звукового движка (Web Audio API):**
  - [x] Внедрить `DynamicsCompressorNode` на мастер-выходе, чтобы при одновременной стрельбе десятков юнитов не возникало перегрузок и клиппинга звука.
  - [x] Привязать громкость и частотную фильтрацию (`BiquadFilterNode`) звуков выстрелов/взрывов к расстоянию от камеры до эпицентра боя.
  - [x] Добавить лимит на максимальное число одновременно создаваемых осцилляторов за один тик (Sound Pooling / Throttling).
- [x] **Балансировка режима выживания (Survival Waves):**
  - [x] Написать скрипт Headless-прогона волн на скорости $1000\times$ для автоматической проверки баланса стоимости юнитов, кулдаунов способностей и силы волн противников.
  - [x] Добавить комбинированные волны врагов, требующие чередования мобильных отрядов и позиционной обороны через `Siege Mode`.

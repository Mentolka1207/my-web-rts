# Architecture: Minimal Web RTS: продуктовая версия (на базе `my-web-rts`)

Дата: 2026-10-30. Основа: `recon.md` (коммит `a1919fb`, 2026-10-29) и `features.csv`. Код перепроверен на текущем
`main`, коммит **`bfd640e`**. Между recon и этим коммитом появились `maps.js`, `storage.js`, `i18n.js`, модальные окна,
PWA. Поэтому каждое утверждение о коде ниже взято из `bfd640e` и даётся со ссылкой `файл:строка`.

**Чем этот план отличается от шаблона пакета.** Шаблон replica-architect рассчитан на SaaS: Postgres, auth, Stripe,
HTTP-роутинг. У одиночной браузерной игры ничего из этого нет, а `AGENTS.md §3.1` прямо запрещает тяжёлые зависимости
и сборщики и требует, чтобы игра запускалась с `file:///`. Поэтому:
- вместо SQL-схемы здесь **контракты данных** (карта, сложность, режим, настройки, профиль) и **инварианты**, которые
  проверяют тесты. Это аналог `check`/`unique` в базе данных;
- вместо HTTP-API здесь **публичные функции модулей** по сценариям F01–F07 из recon.
SQL и сервер появятся, только если ты решишь делать онлайн-рейтинг или мультиплеер. В `features.csv` их нет, кроме
мультиплеера с приоритетом `could` (`features.csv:56`).

## 2. Схема данных (контракты + инварианты)

Контрактов: **5** (MapDef v2, DifficultyDef, ModeDef, Settings v2, Profile v2). Проверка: при загрузке это
**валидатор + миграция** в `storage.js`, при сборке это **юнит-тест каталога карт**. SaveGame (сохранение партии)
в v1 **не делается**: в `features.csv` его нет.

### 2.1 Что есть сейчас и почему это мешает

| факт | где | следствие |
|---|---|---|
| Карта задаётся **функцией** `generateGrid`, а не данными | `maps.js:36-106` | карту нельзя проверить тестом без выполнения кода; `canyon` зависит от состояния глобального PRNG (`maps.js:42-47`) |
| Штабы и кристаллы **одни на все карты**: глобальные константы | `config.js:93-103` | все 3 карты различаются только стенами; разные базы и точки сделать нельзя |
| `GRID_SIZE = 22` используется в 10 файлах | `config.js:88`, `grep -l` по `js/`, `main.js` | размер карты меняется только переписыванием движка; для v1 размер фиксирован |
| Рекорды общие, не по карте/сложности | `storage.js:19-29, 97-120` | рекорд на «Рекруте» перекрывает рекорд на «Ветеране» |
| Чтение хранилища: `Object.assign` без проверки типов | `storage.js:36, 80` | испорченный или старый JSON попадает прямо в настройки (например, `masterVolume: "abc"`) |

### 2.2 MapDef v2: карта как чистые данные

```js
/** @typedef {{col:number,row:number}} Cell */
const MAP_CANYON = {
  schema: 2,
  id: 'canyon',                 // уникален, [a-z0-9-]+
  nameKey: 'MAP_CANYON',        // должен быть в TRANSLATIONS.ru и .en
  size: 22,                     // v1: обязан === GRID_SIZE
  rows: [                       // size строк по size символов: '#' стена, '.' пол
    '######################',
    '#....................#',
    // …
  ],
  playerHQ:   { col: 1,  row: 1  },
  enemyHQ:    { col: 20, row: 20 },
  playerSpawn:{ col: 3,  row: 3  },
  nodes: [ { id: 'alpha', nameKey: 'NODE_ALPHA', col: 0, row: 0 } /* … */ ],
  recommended: { difficulty: 'normal' }   // необязательно
};
```

Переход: один раз запустить текущие `generateGrid` (с сидом 4242 для `canyon`), **запечь** результат в `rows`,
и функции больше не нужны. `applyMapToGrid` (`maps.js:130-194`) читает `rows`, `playerHQ`, `enemyHQ`, `nodes` из MapDef
вместо констант `config.js:93-103`.

**Инварианты** (`tests/maps.test.js`; это аналог constraint в базе, проверяются для каждой карты каталога):
1. `rows.length === size === GRID_SIZE`, каждая строка длины `size`, только символы `#` и `.`.
2. Весь периметр состоит из стен.
3. Клетки HQ непроходимы, кольцо 3×3 вокруг каждого HQ и каждого кристалла свободно (сейчас это делает код
   `maps.js:151-175`, станет проверкой данных).
4. **Достижимость:** BFS (тот же `flowfield.js`) от соседа `playerHQ` доходит до соседа `enemyHQ`, до `playerSpawn`
   и до каждого кристалла. Иначе юниты получают нулевой flow-вектор (поведение описано в recon, F02).
5. `id` карт и `nodes[].id` уникальны; все `nameKey` есть в обоих языках.
6. (баланс, мягкая проверка) расстояние BFS от каждого HQ до ближайшего кристалла отличается не больше чем на N клеток.
   Порог N задаёшь ты, это решение по гейм-дизайну.

### 2.3 DifficultyDef: есть, оставить

`maps.js:6-31`: `allyHpMult`, `enemyHpMult`, `enemyDamageMult`, `waveInterval`, `passiveIncome`. Проверил, что
все пять читаются движком: `units.js:58, 112-117`, `ai.js:10`, `economy.js:19`. Добавить только инвариант в тест:
множители > 0, `waveInterval` ≥ 10 + длительность предупреждения (предупреждение за 10 с, по recon `ai.js:5-8`).

### 2.4 ModeDef: только когда появится второй режим

```js
{ id: 'survival', victory: 'destroyEnemyHQ', defeat: 'loseHQ', waves: true, aiEconomy: false }
// skirmish (features.csv:41, should): aiEconomy: true, waves: false
```
Сейчас режим один, и его условия зашиты в `checkGameOverConditions` (`ui.js:268`). Вводить ModeDef имеет смысл
вместе со skirmish, не раньше.

### 2.5 Settings v2 и Profile v2

```js
// localStorage['rts_neo_settings_v2']
{ schema: 2, masterVolume: 0..1, sfxVolume: 0..1, musicVolume: 0..1,
  shadows: boolean, language: 'ru'|'en', difficulty: 'easy'|'normal'|'hard', mapId: <id из каталога> }

// localStorage['rts_neo_profile_v2']
{ schema: 2, tutorialCompleted: boolean,
  totals: { matchesPlayed, victories, defeats, energyHarvested, bossesKilled },     // целые ≥ 0
  records: { [mapId]: { [difficulty]: { wins, losses, bestWave, maxKills, fastestWinSec|null } } } }
```

Правила: каждое поле проверяется по типу и диапазону; неизвестные ключи отбрасываются; невалидное значение заменяется
значением по умолчанию. **Миграция v1→v2:** если есть `*_v1`, перенести настройки как есть, а общие рекорды v1 записать
в `records[mapId из настроек v1][difficulty из настроек v1]`. Это допущение: в v1 не хранилось, на какой карте поставлен
рекорд. Ключи v1 после успешной миграции удалить.

## 4. Части, которые кусаются

Замеры этого раздела сделаны 2026-10-30 на `bfd640e`: Playwright + headless Chromium + SwiftShader, `renderer.info`.
Число draw calls от GPU не зависит; **FPS я не измерял**: в песочнице нет видеокарты.

- **Карты как данные (риск 1).** Штабы и кристаллы глобальные (`config.js:93-103`), размер сетки зашит в 10 файлах.
  `features.csv:40` отмечает «Несколько карт» как `yes`, но фактически это 3 раскладки стен на одной схеме баз.
  Пока это не исправлено, весь объём контента (оценка recon: L, около квартала) упирается в правку кода под каждую карту.
- **Обновления через Service Worker (риск 2).** Стратегия cache-first с фиксированным именем
  `minimal-web-rts-v2` (`sw.js:5, 58-82`): установленная PWA не получит новую версию, пока имя кэша не сменят вручную.
  В списке прекэша (`sw.js:6-37`) **нет `js/particles.js` и `js/sim_worker.js`**, хотя `particles.js` подключается
  в `index.html:377`. Они докэшируются при первой онлайн-загрузке (`sw.js:67-75`), но первая установка неполная.
  Решение: имя кэша = версия из `package.json`, список файлов генерируется скриптом, тест сверяет его с `index.html`.
- **Мобильная производительность (риск 3).** Старт партии (5 союзников, 3 врага), все 3 карты: **107 draw calls
  с тенями, 87 без** (было 339 / 107 в recon при 8 юнитах; стены теперь инстансированы, `terrain.js:460`).
  В сцене 75 обычных `Mesh` против 12 `InstancedMesh`; 74 из 75 лежат внутри `Group` (составные модели HQ, кристаллов,
  периметра; разбор по типам — мой замер). Следующий шаг: слить статичные части HQ и кристаллов. На реальных
  телефонах FPS не проверен, это нужно сделать до релиза.
- **Локализация неполная.** Оповещения способностей зашиты по-русски (`units.js:301-307`), статусы панели
  способностей тоже (`ui.js:571-641`: «ГОТОВО», «ОСАДА (ВКЛ)», «МОБИЛЬНЫЙ»), счётчики профайлера
  (`ui.js:433, 443, 521`). В EN-версии игрок увидит русский текст. `features.csv:13` («полная двуязычность»)
  нужно понизить до `partial`. Защита от повтора: тест, который ищет кириллицу в строковых литералах вне `i18n.js`.
- **Детерминизм.** Очередь flow field обрабатывается раз в **кадр**, вне фиксированного тика (`main.js:473-479`),
  приказы применяются сразу. Для одиночной игры это не важно; для реплеев или lockstep-мультиплеера придётся
  переделывать. `canyon` перезапускает глобальный PRNG сидом 4242 при каждой генерации (`maps.js:42-43`), и от этого
  зависят последующие броски ИИ (`ai.js:312`). После запекания карт (§2.2) этот побочный эффект исчезнет.
- **Хранилище.** `localStorage` может быть недоступно или переполнено: вызовы уже обёрнуты в `try/catch`
  (`storage.js:32-40, 67-72`), игра продолжит работу без сохранения. Не хватает валидации и миграции (§2.5).
- **Порядок скриптов.** 27 скриптов в глобальном пространстве с проверками `typeof X !== 'undefined'` повсюду
  (пример: `units.js:58`). Новый модуль, подключённый не в том месте, ломается **молча**. Тест-обвязка
  `tests/helpers/loadGame.js` уже грузит реальные файлы, и её стоит использовать для smoke-теста порядка загрузки.
- **Headless-баланс всё ещё копия.** `scripts/headless_wave_test.js:8-19` объявляет свои `DRONE_TYPES`/`ENEMY_TYPES`,
  а не читает `config.js`. `features.csv:52` пишет «синхронизирован», но при следующей правке баланса значения разойдутся.
  Решение: грузить `config.js`, `maps.js`, `ai.js` через `loadGame.js`.
- **Лицензия своего кода.** `LICENSE` по-прежнему MIT (`LICENSE:1-3`), а `features.csv:12` отмечает решение как `yes`.
  `THIRD_PARTY_LICENSES.md` описывает three.js и перечисляет собственные компоненты, но лицензию на них не меняет.
  Пока `LICENSE` = MIT, любой может законно продавать копию этой версии. Я не юрист: это вопрос к юристу до релиза.
- **Документация.** `AGENTS.md §2.5` всё ещё упоминает `PCFSoftShadowMap`; движок использует `PCFShadowMap`
  (по замеру `renderer.shadowMap.type === 1`, в Three.js это значение константы PCFShadowMap; в коде `PCFSoft` не найден).
- Не применимо: часовые пояса, идемпотентность вебхуков, гонки в БД, rate limits, email, GDPR-удаление
  (персональных данных нет: профиль хранится только в браузере игрока).

# 🛰️ AGENTS.md — Руководство для AI-агентов (Minimal Web RTS)

Данный документ содержит правила, архитектурные соглашения и инструкции для AI-агентов, работающих с кодовой базой **my-web-rts**.

---

## 📌 1. Обзор проекта

**Minimal Web RTS** — это трёхмерная стратегия в реальном времени (RTS) в браузере на базе **Three.js** (WebGL).
* **Стек:** Ванильный JavaScript (ES6+), Three.js, HTML5 Canvas, CSS.
* **Автономность:** Проект запускается прямо в браузере (включая работу по протоколу `file:///` без необходимости запуска локального веб-сервера или сборщиков).
* **Ключевые файлы:**
  * `index.html` — HTML-каркас и разметка интерфейса.
  * `style.css` — стили оформления и адаптивный дизайн.
  * `main.js` — исполняемый код игры (логика FSM, Three.js рендер, поиск пути, эффекты).
  * `libs/three.min.js` — автономная библиотека Three.js (v0.186.1, работающая без интернета и CORS).
  * `README.md` — пользовательская и техническая документация.

## ⚙️ 2. Архитектура и ключевые подсистемы

При модификации или расширении игры агент обязан учитывать существующие архитектурные решения:

### 2.1. Навигация и поиск пути (Flow Fields)
* **Принцип:** Никакого персонального A* для каждого юнита. Используется сеточный метод векторных полей потоков:
  1. `Cost Field` — проходимость ячеек (стены и базы блокируют проход).
  2. `Integration Field` — волновой алгоритм (BFS / Дейкстра) расчёта расстояния до цели.
  3. `Flow Field` — векторное поле градиента наименьшего сопротивления.
* **Двойное поле потоков:**
  * Одно поле управляет приказами игрока для союзников.
  * Второе независимое поле непрерывно ведёт вражеские волны к штабу игрока, исключая конфликты маршрутов.

### 2.2. Формации (Formations)
* Поддерживаются режимы построения **Шеренга (Line)** и **Клин (Wedge)**.
* Матрица смещений юнитов динамически ориентируется по вектору движения группы.
* Юниты плавно интерполируют между вектором глобального Flow Field и персональной точкой в строю при приближении к финишу.

### 2.3. Конечный автомат юнитов (FSM)
Юниты функционируют по стейт-машине:
* `IDLE` — патрулирование/сканирование радиуса видимости.
* `MOVE` — движение по вектору Flow Field.
* `CHASE` — сближение с обнаруженной или назначенной целью.
* `ATTACK` — огонь на дистанции поражения с учётом кулдауна оружия.
* Штабы (`HQ`) участвуют в логике боя как полноценные цели наивысшего приоритета при отсутствии более близких юнитов.

### 2.4. Экономика и типы юнитов
* **Энергия:** базовый пассивный доход (+5/сек) + контроль ресурсных точек (+3/сек за каждую захваченную точку) + награда за фраги (+10 за уничтожение дрона).
* **Точки сбора ресурсов:** 3 кристаллических генератора («Альфа», «Центр», «Бета») с кольцом захвата, 3D шкалой прогресса и отображением на миникарте.
* **Классы юнитов:**
  * `Дрон` (сбалансированный): 70⚡, размер 1.0, скорость 6, урон 15, HP 100.
  * `Разведчик` (быстрый/лёгкий): 40⚡, размер 0.5, скорость 12, урон 6, HP 55.
  * `Танк` (тяжёлый/осадный): 150⚡, размер 1.4, скорость 3, урон 45, HP 220.

### 2.5. Процедурная графика и эффекты
* **Без внешних текстур:** Все sci-fi текстуры и материалы генерируются программно через HTML5 Canvas во избежание CORS-ошибок при открытии через `file:///`.
* **VFX:** Обломки взрывов (кубики с гравитацией), вспышки лазеров, лимитированный пул декалей опалённой земли (макс. 60).
* **3D Billboarding:** Полоски здоровья всегда ориентируются на камеру.

### 2.6. Кроссплатформенность и управление
* Полная поддержка **десктопа** (ЛКМ — рамка/выделение, ПКМ — приказ, WASD/колесо — камера) и **мобильных/тач устройств** (тап, рамка пальцем, pinch-zoom, перемещение двумя пальцами, миникарта).

## 📋 3. Правила и ограничения для AI-агентов

1. **Сохранение нулевой конфигурации:**
   * Не добавлять внешние тяжеловесные зависимости через npm или сложные сборщики без явного указания пользователя.
   * Код должен сохранять возможность запуска простым двойным кликом по `index.html`.
2. **Производительность Three.js и WebGL:**
   * Не создавать лишние объекты (`new THREE.Vector3()`) в главном цикле `requestAnimationFrame` — переиспользовать существующие временные переменные для предотвращения пауз Garbage Collector.
   * Контролировать количество источников света и геометрии частиц.
3. **Целостность документации:**
   * При изменении характеристик юнитов, кулдаунов, логики волн или управления — **обязательно синхронизировать** `README.md` и блок `#instructions` в интерфейсе.
4. **Физика расталкивания:**
   * При изменении размеров юнитов или механики спавна проверять алгоритм разделения (separation / obstacle push-back), чтобы дроны не застревали в стенах или друг в друге.

# 🛰️ AGENTS.md — Руководство для AI-агентов (Minimal Web RTS)

Данный документ содержит правила, архитектурные соглашения и инструкции для AI-агентов, работающих с кодовой базой **my-web-rts**.

---

## 📌 1. Обзор проекта

**Minimal Web RTS** — это трёхмерная стратегия в реальном времени (RTS) в браузере на базе **Three.js** (WebGL).
* **Стек:** Ванильный JavaScript (ES6+), Three.js, HTML5 Canvas, CSS.
* **Автономность:** Проект запускается прямо в браузере (включая работу по протоколу `file:///` без необходимости запуска локального веб-сервера или сборщиков).
* **Ключевые файлы и модульная структура (27 скриптов):**
  * `index.html` — HTML-каркас, разметка интерфейса и упорядоченное подключение скриптов.
  * `style.css` — стили оформления, неоновый UI, экраны меню/паузы/статистики и адаптивный мобильный дизайн.
  * `main.js` — главный оркестратор и детерминированный игровой цикл `animate()` на фиксированном шаге 30 Гц.
  * `js/` — директория модулей игры:
    * `config.js` — глобальные константы, характеристики юнитов, scratch-векторы, дебаггер.
    * `i18n.js` — словарь и система мгновенного переключения языков (RU / EN) на лету.
    * `storage.js` — **Storage Schema v2**: сохранение настроек и профиля в `localStorage`, изолированные рекорды по картам/сложности, валидация и миграция `v1 → v2`.
    * `maps.js` — **MapDef v2**: 4 тактические карты как чистые данные (Каньон, Арена, Лабиринт, Перекрёсток), валидатор инвариантов `validateMapDef` и настройки сложности.
    * `prng.js` — сидируемый детерминированный 32-битный генератор псевдослучайных чисел Mulberry32.
    * `audio.js` — процедурный звуковой движок на Web Audio API (выстрелы, щиты, взрывы, способности, оповещения, космический эмбиент, раздельные каналы громкости).
    * `grid.js` — сетка проходимости, препятствия, конвертация координат (`worldToGrid`, `gridToWorld`), проверка видимости (`hasLineOfSight`) и обход углов (`findBypassDirection`).
    * `spatialhash.js` — пространственное хеширование (Spatial Grid) для быстрого $O(1)$ поиска целей и строгого $O(N)$ расталкивания без аллокаций.
    * `formations.js` — тактические построения (шеренга [Z], клин [X], кольцо [C]).
    * `flowfield.js` — высокопроизводительный Flow Field (волновой BFS на `Int32Array`, Cost/Integration/Flow Fields, LRU-кэш).
    * `simulation.js` — Data-Oriented SoA симуляция игрового мира на типизированных массивах (`Float32Array`, `Uint8Array`).
    * `sim_worker.js` — прототип Web Worker для выноса симуляции в фоновый поток через Transferable Objects.
    * `scene.js` — Three.js сцена, камера, свет, рендер с ACESFilmicToneMapping, тени PCFShadowMap, утилита `mergeBufferGeometries`.
    * `terrain.js` — процедурные текстуры земли и стен, InstancedMesh препятствий, энерго-рельсы периметра.
    * `healthbar.js` — 3D полоски HP и щита (Billboarding с компенсацией вращения).
    * `models.js` — 3D модели дронов, флагмана-Левиафана и штабов фракций со слитной геометрией каркасов.
    * `instancing.js` — GPU Instanced Rendering (сборные меши юнитов, инстансированные 3D-биллборды в вершинном шейдере, лазеры и кольца).
    * `particles.js` — пул частиц на одном `THREE.Points` (512 слотов, 1 Draw Call, swap-remove): искры попаданий, обломки взрывов.
    * `effects.js` — Object Pooling пулов лазеров, вспышек и следов; взрывы и искры делегирует в `particles.js`.
    * `units.js` — коллекция и фабрика юнитов, физика анимаций, кулдауны и применение способностей (Форсаж, Щит, Осада).
    * `resources.js` — кристаллы ресурсов, логика захвата и слитная геометрия кристаллов-спутников.
    * `economy.js` — энергия, доход и производство с кольцевым поиском свободных ячеек.
    * `ui.js` — интерфейс, меню, модальные окна (пауза, настройки, рекорды, обучение, лицензии), тактические оповещения, завершение игры, авто-пауза.
    * `ai.js` — ИИ врагов, логика составных волн (Штурмовики, Разведчики, Танки, Босс) и диверсионные группы.
    * `minimap.js` — миникарта с оффскрин-кэшированием препятствий.
    * `benchmark.js` — встроенный стресс-тест производительности сцены (от 100 до 1500 юнитов, переключатели Spatial/Naive и Instancing/Meshes).
    * `input.js` — мышь, зажатое колёсико (MMB), сенсор/тач, WASD, пауза (Esc/P), горячие клавиши способностей и строя.
  * `scripts/headless_wave_test.js` — быстрый headless-тест баланса волн выживания на 1000x скорости без WebGL.
  * `libs/three.min.js` — автономная библиотека Three.js (v0.186.1, работающая без интернета и CORS).
  * `THIRD_PARTY_LICENSES.md` — лицензии сторонних библиотек (Three.js MIT).
  * `manifest.json`, `sw.js` — PWA-манифест и Service Worker v0.2.0 для офлайн-игры (прекэш всех 27 скриптов).
  * `README.md` — пользовательская и техническая документация.

## ⚙️ 2. Архитектура и ключевые подсистемы

При модификации или расширении игры агент обязан учитывать существующие архитектурные решения:

### 2.1. Навигация и поиск пути (Flow Fields)
* **Принцип:** Никакого персонального A* для каждого юнита. Используется сеточный метод векторных полей потоков:
  1. `Cost Field` — проходимость ячеек (1 для свободных, 255 для препятствий).
  2. `Integration Field` — волновой алгоритм поиска в ширину (BFS на 4-связной сетке с равными весами на `Int32Array`) расчёта расстояния до цели.
  3. `Flow Field` — векторное поле градиента наименьшего сопротивления с LRU-кэшированием до 16 целей.
* **Двойное поле потоков:**
  * Одно поле управляет приказами игрока для союзников.
  * Второе независимое поле непрерывно ведёт вражеские волны к штабу игрока, исключая конфликты маршрутов.

### 2.2. Формации (Formations)
* Поддерживаются три режима тактического строя: **Шеренга (Line, [Z])**, **Клин (Wedge, [X])** и **Кольцо (Circle, [C])**.
* Матрица смещений юнитов динамически ориентируется по вектору движения группы.
* В построении «Кольцо» радиус круговой обороны динамически масштабируется по числу юнитов отряда.
* Юниты плавно интерполируют между вектором глобального Flow Field и персональной точкой в строю при приближении к финишу.

### 2.3. Конечный автомат юнитов (FSM)
Юниты функционируют по стейт-машине:
* `IDLE` — патрулирование/сканирование радиуса видимости через Spatial Grid.
* `MOVE` — движение по вектору Flow Field.
* `CHASE` — сближение с обнаруженной или назначенной целью с огибанием углов препятствий.
* `ATTACK` — огонь на дистанции поражения с учётом кулдауна оружия.
* Штабы (`HQ`) участвуют в логике боя как полноценные цели наивысшего приоритета при отсутствии более близких юнитов.

### 2.4. Экономика и типы юнитов
* **Энергия:** базовый пассивный доход (+5/сек на нормальной сложности) + контроль ресурсных точек (+3/сек за каждую захваченную точку) + награда за фраги (+10 за уничтожение дрона).
* **Точки сбора ресурсов:** 3 кристаллических генератора («Альфа», «Центр», «Бета») с кольцом захвата, 3D шкалой прогресса и отображением на миникарте.
* **Классы союзных юнитов:**
  * `Дрон` (сбалансированный): 70⚡, размер 1.0, скорость 6, урон 15, HP 100. Способность: **Энергетический щит [E / 1]** (+50 HP на 6с, кд 12с).
  * `Разведчик` (быстрый/лёгкий): 40⚡, размер 0.5, скорость 12, урон 6, HP 55. Способность: **Форсаж [Q / 2]** (+80% скорости на 3с со шлейфом двигателей, кд 10с).
  * `Танк` (тяжёлый/осадный): 150⚡, размер 1.4, скорость 3, урон 45, HP 220. Способность: **Осадный режим [R/F / 3]** (дальность огня x2, урон по площади 2.2 ячейки, кд 2.5с).
* **Вражеские классы и эволюция волн:**
  * `Штурмовик` (базовый враг): HP 85, скорость 4.5, урон 12.
  * `Разведчик` (с волны 3+): HP 50, скорость 8.5 (молниеносный фланговый наскок), урон 6.
  * `Танк` (с волны 5+): HP 240, скорость 2.6 (осадный таран), урон 35.
  * `Левиафан` (Босс 10-й волны): HP 600, Щит 400 (поглощает урон), скорость 1.8, урон 38 (залповый огонь по 3 целям). Награда: +100⚡.
* **Ответные действия ИИ:** при удержании игроком 3/3 точек вражеский штаб отправляет диверсионный отряд (2 Разведчика + 1 Танк) на отбитие ближайшей точки сбора.

### 2.5. Процедурная графика, PBR-текстуры и эффекты
* **Zero Assets & PBR-текстуры:** Все sci-fi текстуры генерируются динамически через HTML5 Canvas без внешних файлов (`file:///` совместимость). Используются процедурные карты диффузного цвета (Albedo 512x512), рельефа (`bumpMap`) и шероховатости (`roughnessMap`) для реалистичного бликования металлических плит, швов и заклепок.
* **Освещение и постобработка:** Включен кинематографичный тональный компрессор `ACESFilmicToneMapping` (экспозиция 1.15), контактные тени `PCFShadowMap` (2048x2048) и контурный свет `Rim Light` для четкого выделения силуэтов юнитов.
* **GPU Instancing и слияние статической геометрии:**
  * Стены и оголовки карты отрисовываются через два `THREE.InstancedMesh`.
  * Элементы периметра, каркасы штабов и спутники кристаллов объединены через `mergeBufferGeometries`, сократив 31 меш сцены.
  * Армия объединена в композитные PBR-геометрии (`instancing.js`), сокращая Draw Calls до ~16 на всю сцену.
* **VFX & Частицы:** Пул частиц `THREE.Points` (512 слотов, 1 Draw Call, swap-remove, zero-allocation), вейпоинт-маркеры приказов, лучистый крестообразный блик оптики вспышек, кратеры с тлеющим ядром и трещинами (макс. 60 декалей), неон-шлейфы форсажа.
* **3D Billboarding:** Полоски здоровья ориентируются на камеру с компенсацией вращения родительского юнита (в инстансированном режиме — прямо в вершинном шейдере на GPU).

### 2.6. Кроссплатформенность и управление
* **Десктоп:** ЛКМ — рамка/выделение, ПКМ — приказ перемещения или фокус-атака врага/штаба, зажатое колёсико мыши (MMB) — перетаскивание карты 1:1, вращение колеса — зум, WASD/стрелки — панорама, F3 — Debug Overlay, `` ` `` (Backquote) — компактная панель FPS / времени кадра / числа юнитов (`#perf-panel`), клавиши `Z`, `X`, `C` — построения, клавиши `Q`, `E`, `R`/`F` (или `1`, `2`, `3`) — способности.
* **Мобильные/тач устройства и сенсор:** переключатель режимов `[🖐 Карта / ⬚ Рамка]`, свайп одним пальцем в режиме карты — плавное перемещение, свайп в режиме рамки или hold — выделение группы, тап — выделение юнита/приказ, pinch-zoom и панорама двумя пальцами, миникарта.

### 2.7. Пространственное хеширование и физика (Spatial Grid)
* **Принцип:** Пространственная сетка `spatialGrid` (ячейка 4.0) разделяет юнитов по корзинам.
* **Поиск врагов:** $O(1)$ запрос ближайшей цели `spatialGrid.findNearest(pos, visionRange, 'enemy')` по окрестным ячейкам.
* **Расталкивание (Separation):** Проверка коллизий выполняется только внутри ячейки и с 4 смежными направлениями. Сложность снижена с $O(N^2)$ до $O(N)$ без создания новых объектов (Zero-allocation).
* **Обход углов стен (CHASE):** Функция `hasLineOfSight` лучевой проверкой (Bresenham) определяет видимость цели; при блокировке функция `findBypassDirection` направляет юнита вокруг угла стены.

### 2.8. Процедурный звук (Web Audio API)
* **Zero Assets & Zero CORS:** Все звуковые эффекты (выстрелы дронов, тяжелые пушки танков, лучи босса, попадания, поглощение урона щитами, взрывы, клики интерфейса, способности) синтезируются процедурно через `AudioContext` (осцилляторы, шумовые буферы, огибающие ADSR и фильтры BiquadFilter).
* **Фоновый эмбиент:** Процедурный sci-fi космический гул (drone) на базе расстроенных синусоидальных осцилляторов и низкочастотной фильтрации с гармоническими смещениями.
* **Политика автовоспроизведения:** Инициализация контекста звука отложена до первого пользовательского взаимодействия (клик, тач, клавиша) либо нажатия «Играть».
* **Управление звуком:** Кнопка `#sound-toggle-btn` в шапке панели инструкций позволяет мгновенно включать и выключать звук (`🔊 / 🔇`).

## 📋 3. Правила и ограничения для AI-агентов

1. **Сохранение нулевой конфигурации:**
   * Не добавлять внешние тяжеловесные зависимости через npm или сложные сборщики без явного указания пользователя.
   * Код должен сохранять возможность запуска простым двойным кликом по `index.html`.
2. **Производительность Three.js и WebGL:**
   * Не создавать лишние объекты (`new THREE.Vector3()`) в главном цикле `requestAnimationFrame` — переиспользовать существующие временные переменные для предотвращения пауз Garbage Collector.
   * Контролировать количество источников света и геометрии частиц.
3. **Целостность документации:**
   * При изменении характеристик юнитов, кулдаунов, логики волн или управления — **обязательно синхронизировать** `README.md` и блок `#instructions` в интерфейсе.
4. **Физика расталкивания:**
   * При изменении размеров юнитов или механики спавна проверять алгоритм разделения (separation / obstacle push-back), чтобы дроны не застревали в стенах или друг в друге.

# 🛰️ Как заставить 1 000+ 3D-юнитов не застревать в узком проходе: Flow Fields и Spatial Hashing в браузере

> Архитектурный разбор высокопроизводительного поиска пути и разделения коллизий в Three.js на примере браузерной RTS без внешних зависимостей.

---

## 1. Проблема: почему индивидуальный A* умирает при масштабировании

В большинстве обучающих материалов по разработке RTS навигацию объясняют через классический алгоритм **A\***. Для 10–20 юнитов это работает приемлемо. Однако когда игрок выделяет отряд из 300 дронов и отправляет их через узкий каньон в центр карты, движок сталкивается с тремя непреодолимыми проблемами:

1. **Вычислительная сложность $O(N \times (V \log V + E))$**: каждый из 300 юнитов строит собственный граф путей к одной и той же целевой точке. В JavaScript это приводит к длительным блокировкам главного потока (Long Tasks > 50 ms) и падению FPS со стабильных 60 до 5–10 кадров.
2. **Толкучка в «бутылочных горлышках» (Bottlenecks)**: каждый юнит стремится строго по одной идеальной центральной линии. В узком проходе юниты врезаются друг в друга, застревают в углах стен и начинают судорожно пересчитывать маршруты заново.
3. **Garbage Collector (GC Thrashing)**: постоянное создание объектов узлов графа (`{ x, y, g, h, f, parent }`) порождает мегабайты мусора в секунду, вызывая периодические микрофризы.

---

## 2. Решение: Векторные поля потоков (Flow Fields)

Векторное поле потоков переворачивает парадигму: **вместо расчёта пути для каждого юнита мы рассчитываем один общемировой векторный градиент для цели, а тысячи юнитов лишь считывают направление за $O(1)$**.

Архитектура состоит из трёх слоёв:

```
[ Cost Field ] ──> [ Integration Field (BFS) ] ──> [ Flow Field (Gradients) ] ──> O(1) Lookup
(Проходимость:      (Волновой расчёт расстояний        (Векторы наименьшего         (Юниты плывут
1 = свободно,        до цели от 0 до Max)              сопротивления 8 направлений)  по градиенту)
255 = стена)
```

### Реализация на плоских типизированных массивах (Int32Array)

В `js/flowfield.js` карта представлена плоским одномерным массивом `Int32Array(GRID_SIZE * GRID_SIZE)`:

```javascript
// Расчёт карты интеграции методом поиска в ширину (BFS на Int32Array)
computeIntegrationField(targetCol, targetRow) {
    this.integrationField.fill(65535);
    const targetIdx = targetRow * this.gridSize + targetCol;
    this.integrationField[targetIdx] = 0;

    let head = 0, tail = 0;
    this.bfsQueue[tail++] = targetIdx;

    while (head < tail) {
        const curr = this.bfsQueue[head++];
        const cx = curr % this.gridSize;
        const cy = (curr / this.gridSize) | 0;
        const currentDist = this.integrationField[curr];

        // 4 ортогональных соседа (dx, dy)
        for (let i = 0; i < 4; i++) {
            const nx = cx + DX[i], ny = cy + DY[i];
            if (nx < 0 || nx >= this.gridSize || ny < 0 || ny >= this.gridSize) continue;
            const nIdx = ny * this.gridSize + nx;
            if (this.costField[nIdx] >= 255) continue; // Препятствие

            const newDist = currentDist + 1;
            if (newDist < this.integrationField[nIdx]) {
                this.integrationField[nIdx] = newDist;
                this.bfsQueue[tail++] = nIdx;
            }
        }
    }
}
```

### Генерация поля векторов (Flow Field)
Каждая ячейка опрашивает своих 8 соседей и выбирает направление максимального падения интеграционного значения:

```javascript
// Извлечение нормализованного вектора направления
const flowVector = flowField[row][col];
unit.velocity.lerp(flowVector, 0.25).normalize();
```

Юниты в радиусе 1.6 клеток до цели плавно замедляются, предотвращая вибрации и толчею:
```javascript
if (distanceToGoal < 1.6) {
    currentSpeed *= Math.max(0.25, distanceToGoal / 1.6);
}
```

### Двойное независимое поле потоков
Чтобы марш вражеских волн не сбивался, когда игрок отдаёт союзникам приказы кликом ПКМ, движок поддерживает **два параллельных поля потоков**:
1. `flowFieldGen` — ведёт союзные отряды к точке приказа.
2. `enemyFlowFieldGen` — непрерывно направляет вражеские отряды на штаб игрока.

## 3. Пространственное хеширование (Spatial Grid): $O(N)$ вместо $O(N^2)$

Когда 1 000+ юнитов сходятся в одной точке, наивная проверка столкновений каждого с каждым требует:

$$\frac{N \times (N - 1)}{2} = \frac{1500 \times 1499}{2} \approx 1\,124\,250 \text{ проверок за кадр!}$$

При 60 FPS это **67 миллионов проверок в секунду**, что моментально вешает браузер.

### Решение: Пространственная сетка корзин (Spatial Hashing)

Мы делим карту размером $48 \times 48$ на корзины размером $4.0 \times 4.0$ (`js/spatialhash.js`):
1. **Распределение за $O(N)$**: каждый юнит по своим мировым координатам помещается в список ячейки:
   $$\text{col} = \left\lfloor \frac{x + \text{halfMap}}{\text{cellSize}} \right\rfloor, \quad \text{row} = \left\lfloor \frac{z + \text{halfMap}}{\text{cellSize}} \right\rfloor$$
2. **Проверка только со смежными ячейками**: для исключения дублирования пара проверяется только внутри своей ячейки и с 4 соседями (Восток, Юго-Восток, Юг, Юго-Запад).
3. **Число проверок пар падает с 1 124 250 до ~4 500!** Ускорение более чем в **250 раз**!

### Двухэтапная релаксация и осадный режим
При коллизии юнитов учитывается их масса и состояние:
- Если юнит находится в **Siege Mode (Осадный режим)**, он обладает бесконечной инерцией относительно союзников. Отталкивается только подвижный юнит, а осадная платформа остаётся неподвижной.
